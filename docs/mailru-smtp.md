# Подключение Mail.ru

Статус на 11 сентября 2026: production подключён к SMTP Mail.ru для `kredavto@mail.ru`.
Проверены TLS и SMTP-аутентификация из API и фонового worker; endpoint здоровья — HTTP 200.
Проверка не отправляла писем. Доставка во входящие требует отдельного теста на согласованный адрес.
При создании кампании в поле отправителя выбирайте/вводите `kredavto@mail.ru`.
Другие адреса из редактируемого списка сами по себе не подключают другие почтовые аккаунты.

Официальная инструкция: https://help.mail.ru/mail/login/mailer/

- Создайте отдельный пароль приложения с правом **Только отправка писем в Почте**.
- Используйте полный email как SMTP_USERNAME и разрешённый адрес From.
- SMTP_HOST=smtp.mail.ru, SMTP_PORT=465, SMTP_USE_TLS=true, EMAIL_PROVIDER=smtp.
- SMTP_USE_TLS на 465 означает TLS сразу; на других портах — обязательный STARTTLS.
- Проверка сертификата включена библиотекой по умолчанию. Не отключать её.
- SMTP_PASSWORD — только серверный секрет. Не добавлять в frontend/Vercel public vars/Git.

## Локальный безопасный ввод на Windows

`infrastructure/windows/Save-SmtpCredential.ps1` открывает маскированное поле.
Сохранение создаёт `%LOCALAPPDATA%/PremiumB2BMailer/credentials/smtp.credential.xml`.
Пароль защищён DPAPI текущего пользователя Windows, каталог доступен только ему.
Файл не находится в проекте/OneDrive. Окно не передаёт пароль на сервер и не запускает отправку.
Не печатать содержимое credential, не передавать пароль через аргументы процесса или чат.
При завершении подключения расшифровать только в памяти и передать по проверенному SSH
через stdin. На сервере — файл с правами 0600, без вывода значений или SMTP debug-логов.

## Проверки перед переключением production

1. Проверить очередь, запланированные кампании и задания уведомлений; не активировать
   старые тестовые задания без отдельного согласования.
2. Проверить исходящее TLS-соединение из API и worker. Worker подключён к отдельной
   outbound-сети для исходящих соединений; база данных и Redis остаются в internal-сети.
3. Проверить SMTP-аутентификацию без MAIL FROM / RCPT TO / DATA, то есть без отправки письма.
4. Настроить From и адрес системных уведомлений; сохранить резервную копию конфигурации
   с такими же ограниченными правами; обновить только необходимые параметры.
5. Пересоздать нужные контейнеры и проверить здоровье. Тестовое письмо отправлять только
   на согласованный адрес. Успешная SMTP-аутентификация не подтверждает доставку.
6. Не запускать рассылку по базе автоматически и не обходить ограничения Mail.ru.

- Сохранена резервная копия кода и предыдущего env в закрытом серверном каталоге
  `/opt/premium-b2b-mailer/backups/mailru-smtp-20260911/`.
- Изменены только SMTP-параметры, домен отправителя и From системных уведомлений.
  Остальные переменные окружения проверены на неизменность.
- `.env` имеет права 0600. Одноразовая серверная промежуточная копия пароля удаляется
  после успешной проверки; локальная копия остаётся зашифрованной DPAPI.
- При необходимости отката используйте `env.before` из резервной копии с правами 0600
  и пересоздайте API/worker/beat. Не печатайте env или полный вывод Compose config.
