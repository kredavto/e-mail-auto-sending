# ИИ-помощник Premium B2B Mailer

## Пользовательский сценарий

1. Войдите, выберите пространство и откройте **ИИ-помощник**.
2. Выберите задачу: письмо, следующие шаги или расписание. Для улучшения письма
   выберите сохранённый шаблон. Несохранённый текст редактора модели не передаётся.
3. Укажите продукт, аудиторию, цель, стиль, проверенные факты и при необходимости
   URL для CTA. Нажмите **Спросить ИИ**. Результаты и ошибки сохраняются в личной
   истории на сервере; последние 30 показаны в интерфейсе. API позволяет получить
   любую свою запись по `GET /api/v1/assistant/runs/{id}`.
4. **Сохранить как новый шаблон и открыть** создаёт отдельный шаблон. Проверьте
   факты, подстановку данных и HTML кнопкой **Проверить письмо**. Изменения в
   открытом старом шаблоне не перезаписываются без стандартного предупреждения.
5. В **Новая рассылка** заполните отправителя, продукт, время в МСК, выберите
   проверенные шаблоны (1–5), интервал повторных писем (1–30 дней) и конкретных
   получателей (до 1000). Поиск работает по email, Ф.И.О. и компании. Отписавшиеся,
   ответившие и адреса с возвратами не предлагаются. Подтвердите основание отправки.
6. **Создать черновик рассылки** ничего не отправляет. Создаёт отдельный продукт,
   email-цепочку и кампанию. Первое письмо запланировано на введённое время;
   повторные — по будням 09:00–18:00 Europe/Moscow.
7. Выберите кампанию. Попросите ИИ помочь с расписанием либо нажмите **Подготовить
   запуск**, **Подготовить паузу** или **Подготовить перенос**. Проверьте адрес
   отправителя, кампанию, число адресатов и дату в карточке результата.
8. Отметьте подтверждение и нажмите **Подтвердить действие**. Только этот запрос
   меняет кампанию. Предложение действует 15 минут и привязано к автору/пространству;
   повторное подтверждение не повторяет действие, изменённая кампания отклоняется.
9. Серверные Celery beat/worker выполняют существующий почтовый pipeline независимо
   от вкладки браузера. `running` означает разрешённую работу планировщика, а не
   подтверждение доставки. Пауза не отзывает уже переданные в очередь/SMTP письма.
   Возобновление может обработать просроченные шаги сразу. Перенос начала разрешён
   только для черновика/паузы до постановки первого письма в очередь.

## Режим доставки и ограничения

Если показано **Тестовая доставка**, используется Mailpit: внешние получатели писем
не получают. Для реальной доставки администратор отдельно настраивает SMTP/SES и
домен отправителя. ИИ не меняет почтовые ключи, DNS, тарифы, согласия и лимиты.
Изменения расписания доступны owner/admin/manager; viewer/operator могут запрашивать
помощь и читать только собственную историю. История — отдельные запросы, не бесконечный
чат: контекст уточняющего запроса нужно указать снова или выбрать шаблон.

## Реализация и безопасность

- Один OpenAI Agents SDK агент (`app/modules/assistant/agent.py`), одна read-only
  функция `workspace_context`, структурированный ответ. Shell, браузера, инструментов
  отправки писем и прямого доступа модели к базе нет.
- В OpenAI уходят запрос, выбранный шаблон и краткие данные выбранной кампании/счётчики.
  Контактная база, пароли и ключи не включаются. `store=False`, tracing отключён.
- `assistant_runs` (миграция `0006_assistant`) сохраняет UUID до вызова модели,
  результат, автора, время, модель, токены и квитанцию подтверждения. Дневной лимит
  30 запросов на пространство (UTC), серийное ограничение приёма на уровне PostgreSQL.
  Таймаут агента 45 секунд, до трёх ходов, до 2200 выходных токенов на вызов модели.
- Оценка цены для GPT-5.6 Luna: $0.20/$1.20 за 1M входных/выходных токенов,
  без скидки кэша. Проверено 2026-09-11 по
  [карточке модели](https://developers.openai.com/api/docs/models/gpt-5.6-luna).
  Для иной модели оценка не подставляется; фактическая стоимость — в OpenAI Billing.
- Черновик преобразуется в разрешённый набор TipTap-блоков; произвольные HTML,
  исполняемые шаблонные выражения и небезопасные CTA запрещены. Отписка сохраняется.
- Изменения кампаний пишутся в существующий неизменяемый аудит. Действия не выполняются
  в процессе генерации; человеческое подтверждение проверяется сервером отдельно.

## Настройка сервера и проверки

В серверном `.env`: `OPENAI_API_KEY`, опционально `OPENAI_MODEL` (gpt-5.6-luna),
`ASSISTANT_DAILY_LIMIT` (30). Только API-контейнер получает ключ; worker/beat он не нужен.
Локальный Python по умолчанию читает `.env`, поэтому для локального запуска передайте
ключ через окружение из согласованного секретного файла. Не добавляйте `VITE_` к ключу.
`.dockerignore` и `.vercelignore` исключают `.env*`; секреты не должны попадать в образы.

Обновление: собрать api/worker/beat, выполнить миграцию под DB owner, пересоздать
сервисы без изменения PostgreSQL/Redis/MinIO, затем публиковать frontend.

Проверки: `python -m pytest tests/test_assistant.py tests/test_alembic_offline.py`;
`pnpm --dir frontend exec playwright test e2e/assistant.spec.ts --workers=1`.
Браузерные тесты используют API-заглушки; серверная проверка выполняется на синтетических
записях внутри откатываемой транзакции с поддельной очередью. Реальная рассылка не запускается.
